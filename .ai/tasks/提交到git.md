# 提交到 git

对当前仓库完成 git 初始化（如需要）与本地提交，并展示最近提交记录。

## 目标

1. 若仓库尚未 `git init`，先完成本地初始化。
2. 将当前变更完成本地提交，提交说明需写清本次提交了什么。
3. 提交成功后向用户展示最近 5 次提交。

## 输入

- 提交备注：说明本次提交了什么。用户未提供时，根据 `git status` / `git diff` 起草，向用户确认后再提交；仍不清楚则先问用户。

## 执行步骤

1. 检查当前目录是否为 git 仓库（例如 `git rev-parse --is-inside-work-tree`）。若不是，执行 `git init`。
2. 并行查看：`git status`、`git diff`（含已暂存与未暂存）、`git log -5`（若尚无提交可跳过 log）。
3. 确认提交范围与备注：
   - 不提交疑似密钥/凭证文件（如 `.env`、`credentials.json` 等）；若用户明确要求提交此类文件，先警告再按用户决定处理。
   - 备注必须说明提交了什么；没有可用备注就先问用户，不要用空信息或无意义占位提交。
4. 暂存相关变更并提交（用 HEREDOC 传递提交说明），例如：
   ```bash
   git add <相关文件>
   git commit -m "$(cat <<'EOF'
   <提交说明：写清提交了什么>

   EOF
   )"
   ```
5. 提交完成后执行 `git log -5 --oneline`（或等价命令），把最近 5 次提交展示给用户；并再跑一次 `git status` 确认工作区状态。

## 产出

- 一次成功的本地 commit（或说明无需提交 / 用户取消的原因）。
- 最近 5 次提交列表（不足 5 次则展示全部）。

## 约束

- 信息不清楚时先问用户，不要擅自假设提交范围或备注。
- 只做本地操作：初始化（如需）+ 暂存 + 提交；除非用户明确要求，否则不 `push`、不改 `git config`、不做 force/rebase 等破坏性操作。
- 不要使用 `--no-verify` 等方式跳过 hooks，除非用户明确要求。
- 若没有可提交变更，说明现状并展示最近提交，不要创建空提交。
