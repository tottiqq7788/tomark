# 拉取远程代码

自动读取 `.ai/remote/` 中的远程信息，配置 origin（如需）并拉取当前分支的远程更新。

## 目标

1. 从 `.ai/remote/` 解析可用的 Git Remote。
2. 确保本地仓库已关联该远程（默认 remote 名为 `origin`）。
3. 将远程当前分支的更新拉取到本地，并向用户报告结果。

## 输入

- 远程信息：优先读取 `.ai/remote/*.md` 中的 `Git Remote` 字段。
- 选择规则：仅一份有效记录时直接使用；多份时优先选与当前项目目录名匹配的记录，其次选用途标明为本项目远程仓库的记录；仍无法唯一确定时再询问。
- 用户若在消息里指定了某份 remote 文件或 URL，优先按用户指定。

## 执行步骤

1. 确认当前目录是 git 仓库；若否，说明需先初始化/提交，停止拉取（可提示先执行「提交到git」）。
2. 读取 `.ai/remote/` 下除 `.gitkeep` 外的 Markdown，提取 `Git Remote`（及仓库名、访问方式等）。
3. 检查现有 `git remote -v`：
   - 若无 `origin`：`git remote add origin <Git Remote>`。
   - 若已有 `origin` 但 URL 与记录不一致：更新为记录中的 URL（`git remote set-url origin <Git Remote>`），并在结果中说明变更。
4. 查看当前分支与状态：`git status -sb`、`git branch --show-current`。
   - 若尚无任何 commit，说明无法拉取并停止。
   - 若存在未提交变更：仍尝试拉取；若会因本地改动冲突而无法安全合并，停止并说明冲突/脏工作区，不要 stash、丢弃或擅自提交。
5. 先更新远程引用：
   ```bash
   git fetch origin --prune
   ```
6. 拉取当前分支更新：
   - 若当前分支已设置上游：`git pull --ff-only`。
   - 若尚未设置上游，但远程存在同名分支：`git pull --ff-only origin HEAD`，成功后设置上游 `git branch --set-upstream-to=origin/<当前分支>`。
   - 若远程不存在同名分支：说明尚无可拉取的远程分支，停止（可提示先执行「推送到远程」）。
7. 若 `--ff-only` 因历史分叉失败：不要改用 merge/rebase/force；向用户报告分叉情况与 `git status -sb`，由用户决定后续策略。
8. 拉取成功后简要展示：使用的 remote 文件、远程 URL、分支名、前后提交对比（如 `git log -5 --oneline`）、`git status -sb` 结果。

## 产出

- 当前分支已快进拉取远程更新（或说明失败/无可拉取原因）。
- 所用 `.ai/remote` 记录路径与 Git Remote URL。

## 约束

- 需求清晰时直接拉取，不要向用户反复确认。
- 仅当远程记录缺失、多份无法唯一判定、或缺少 `Git Remote` 字段导致无法继续时再询问。
- 默认使用 `--ff-only`，禁止 `reset --hard`、`push --force`、丢弃本地改动等破坏性操作，除非用户明确要求。
- 不自动 stash、不自动提交、不自动 rebase/merge 解决分叉。
- 不修改 `git config` 的用户名/邮箱等全局或本地身份配置。
- 不把密码、token、私钥写入仓库或命令历史展示中；若认证失败，说明失败原因与下一步（如检查 gh/SSH 登录），不要要求用户把密钥贴进聊天。
- 只负责拉取相关操作，不顺便做无关重构、提交或推送（提交请用「提交到git」，推送请用「推送到远程」）。
