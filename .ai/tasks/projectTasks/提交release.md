# 提交 release

将**当前设备**上、**最新版本**的安装包发布到远程仓库的 Release；远程信息来自 `.ai/remote/`。

## 目标

1. 确认 `.ai/remote/` 中有可用远程仓库信息。
2. 定位本机已打好的、符合当前设备且为最新版本的安装包。
3. 创建/更新远程 Release 并上传这些安装包，回报 Release 地址与上传文件列表。

## 输入

- 远程信息：`.ai/remote/*.md` 中的 `Git Remote` / 仓库名等（选择规则同「推送到远程」：仅一份则用；多份时优先项目名匹配；用户指定优先）。
- 安装包：按根目录 `agent.md`「打包安装包」中的产物路径查找；版本号优先取最近 git 提交中的 `vX.Y.Z`，其次产物文件名/项目版本字段中的最新版本。
- **若 `.ai/remote/` 无有效远程记录**：询问用户要远程信息（或提示先执行「远程信息初始化」），拿到后再继续；不要猜测远程地址。

## 平台与版本过滤（强制）

只上传**最新版本**，且**仅当前设备对应产物**：

| 当前设备 | 可上传 |
|----------|--------|
| macOS | 该最新版本下的 Intel `.dmg` 与 Apple 芯片 `.dmg`（两套都有则都传；缺哪个说明哪个未找到） |
| Windows | 该最新版本下的 `.exe` 安装包 |
| 其它 | 按 `agent.md` 该平台产物；未约定则说明并停止 |

不要上传其它 OS、其它旧版本、中间构建残留。若本地没有符合条件的安装包，提示先执行「打包安装包」，不要用源码或随意文件凑数。

## 执行步骤

1. 读取 `.ai/remote/`；无可用 `Git Remote` 时询问用户远程信息，问清再继续。
2. 读取 `agent.md` 打包产物约定；识别当前 OS；解析本地应上传的最新版本号与文件路径。
3. 确认远程仓库可访问（如 GitHub 用 `gh` 且已登录；其它宿主按 `agent.md` / 远程类型选用等价方式）。认证失败时说明原因，不要索要明文 token 写入仓库。
4. 以版本号为 Release tag（如 `v0.1.0`，与本地版本规则一致）：
   - 若远程尚无该 tag/Release：创建 Release 并附上安装包。
   - 若已有同名 Release：仅补充/更新**本次应传的、当前设备对应**资产，不要删掉其它平台已上传的包（除非用户明确要求覆盖重建）。
5. 完成后向用户报告：所用远程记录、Release URL、版本号、已上传文件的本地路径与远程资产名。

## 产出

- 远程 Release（新建或更新资产）。
- Release 链接与已上传安装包列表。

## 约束

- 无远程信息必须先问用户，不要编造仓库地址。
- 只推最新版本 + 当前设备产物；不多传、不误传其它平台旧包。
- 需求与远程信息齐全时直接发布，不要反复确认。
- 不修改 `git config`；不把密码/token/私钥写入仓库或对话存档。
- 本任务不负责重新打包（缺包则提示「打包安装包」）；不顺便改业务代码。
- 发布命令与宿主细节以当前项目 `agent.md` / 远程类型为准，任务本身不写死某一技术栈 CLI（可在 `agent.md` 补「提交 release」小节供复用）。
