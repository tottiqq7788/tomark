# 推送到远程

自动读取 `.ai/remote/` 中的远程信息，配置 origin（如需）并推送当前分支。

## 目标

1. 从 `.ai/remote/` 解析可用的 Git Remote。
2. 确保本地仓库已关联该远程（默认 remote 名为 `origin`）。
3. 将当前分支推送到远程，并向用户报告结果。

## 输入

- 远程信息：优先读取 `.ai/remote/*.md` 中的 `Git Remote` 字段。
- 选择规则：仅一份有效记录时直接使用；多份时优先选与当前项目目录名匹配的记录，其次选用途标明为本项目远程仓库的记录；仍无法唯一确定时再询问。
- 用户若在消息里指定了某份 remote 文件或 URL，优先按用户指定。

## 执行步骤

1. 确认当前目录是 git 仓库；若否，说明需先初始化/提交，停止推送（可提示先执行「提交到git」）。
2. 读取 `.ai/remote/` 下除 `.gitkeep` 外的 Markdown，提取 `Git Remote`（及仓库名、访问方式等）。
3. 检查现有 `git remote -v`：
   - 若无 `origin`：`git remote add origin <Git Remote>`。
   - 若已有 `origin` 但 URL 与记录不一致：更新为记录中的 URL（`git remote set-url origin <Git Remote>`），并在结果中说明变更。
4. 查看当前分支与状态：`git status -sb`、`git branch --show-current`。
   - 若存在未提交变更，仍可推送已有 commit；在结果中提醒有本地未提交改动。
   - 若尚无任何 commit，说明无法推送并停止。
5. 推送当前分支并设置上游（首次需要时）：
   ```bash
   git push -u origin HEAD
   ```
6. 推送成功后简要展示：使用的 remote 文件、远程 URL、分支名、`git status -sb` 结果。

## 产出

- 当前分支已推送到远程（或说明失败原因）。
- 所用 `.ai/remote` 记录路径与 Git Remote URL。

## 约束

- 需求清晰时直接推送，不要向用户反复确认。
- 仅当远程记录缺失、多份无法唯一判定、或缺少 `Git Remote` 字段导致无法继续时再询问。
- 禁止 `push --force` / `--force-with-lease` 等强制推送，除非用户明确要求。
- 不修改 `git config` 的用户名/邮箱等全局或本地身份配置。
- 不把密码、 token、私钥写入仓库或命令历史展示中；若认证失败，说明失败原因与下一步（如检查 gh/SSH 登录），不要要求用户把密钥贴进聊天。
- 只负责推送相关操作，不顺便做无关重构或提交（提交请用「提交到git」任务）。
