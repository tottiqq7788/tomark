# 推送到远程

读取 `.ai/remote/` 中的远程信息，确认本地分支与远程分支的同步状态后，再将当前分支安全推送到远程。推送前必须先获取远程最新状态，避免覆盖远程已有提交。

## 目标

1. 从 `.ai/remote/` 解析可用的 Git Remote，并确认 `origin` 配置正确。
2. 推送前执行远程同步检查，明确本地领先、远程领先、双方分叉或完全同步的状态。
3. 远程有更新时，先以不丢失任何一方提交的方式整合，再推送当前分支。
4. 遇到未提交改动、合并冲突、认证失败或权限问题时安全停止并报告原因。

## 输入

- 远程信息：优先读取 `.ai/remote/*.md` 中的 `Git Remote` 字段。
- 选择规则：仅一份有效记录时直接使用；多份记录时优先选择与当前项目目录名匹配的记录，其次选择标明为本项目远程仓库的记录；仍无法唯一确定时再询问用户。
- 用户在消息中指定 remote 文件或 URL 时，优先按用户指定处理。

## 执行步骤

1. 确认当前目录是 Git 仓库；若不是，停止并提示先完成初始化和本地提交。
2. 读取 `.ai/remote/` 下除 `.gitkeep` 外的 Markdown，提取 `Git Remote`、仓库名和访问方式。
3. 检查 `git remote -v`：
   - 没有 `origin`：执行 `git remote add origin <Git Remote>`。
   - 已有 `origin` 但 URL 不一致：执行 `git remote set-url origin <Git Remote>`，并在结果中说明变更。
4. 检查本地工作树和当前分支：
   - 使用 `git status --short --branch`、`git branch --show-current`。
   - 记录是否存在未提交改动；不要自动 stash、丢弃或覆盖这些改动。
   - 如果没有任何本地 commit，停止并提示先执行“提交到git”任务。
5. 获取远程最新状态（不修改工作文件）：

   ```bash
   git fetch --prune origin
   ```

   然后比较当前分支和对应远程分支：

   ```bash
   git rev-list --left-right --count HEAD...origin/<当前分支>
   ```

   输出的两个数字分别表示本地领先提交数和远程领先提交数。若远程分支尚不存在，按首次推送处理。

6. 如果第 4 步发现未提交改动：
   - `fetch` 可以保留，但在 pull、merge 或 push 前停止同步。
   - 提示用户先提交或自行处理工作树改动，然后重新执行本任务；不要自动 stash、丢弃或覆盖这些改动。
7. 在工作树干净时，根据比较结果处理：

   - **本地领先、远程不领先**：直接执行 `git push -u origin HEAD`。
   - **远程领先、本地不领先**：先执行 `git pull --ff-only origin <当前分支>`；快进完成后确认状态，若已同步则无需重复 push。
   - **本地和远程都领先（分叉）**：执行 `git pull --no-rebase origin <当前分支>`，创建普通合并提交以保留双方历史，然后检查合并结果并执行 `git push -u origin HEAD`。
   - **完全同步**：不创建空提交、不重复 push，报告当前已同步。
   - **远程分支不存在**：执行 `git push -u origin HEAD` 创建上游跟踪关系。

8. 若 `pull` 产生冲突：
   - 立即停止，不自动选择一方、不删除冲突文件、不执行 `git reset --hard`。
   - 报告冲突文件和当前 Git 状态，提示用户处理冲突后再继续。
9. 拉取或合并完成后再次执行 `git status --short --branch`，确认不存在未解决冲突，再执行推送。
10. 推送成功后展示：使用的 remote 文件、远程 URL、当前分支、fetch 后的同步判断、实际 pull/merge/push 操作，以及最终 `git status --short --branch`。

## 输出

- 当前分支已安全推送到远程，或明确说明无需推送/停止原因。
- 使用的 `.ai/remote` 记录路径和 Git Remote URL。
- 推送前后的本地领先数、远程领先数，以及是否发生快进或合并。
- 最近提交记录和最终工作树状态。

## 约束

- 推送前必须先执行 `git fetch --prune origin`，不得直接盲推。
- 远程有更新时必须先拉取并整合，再执行 push。
- 默认使用普通合并保留双方历史；不擅自 rebase 已存在的本地提交。
- 禁止 `push --force`、`push --force-with-lease`、`reset --hard`、删除远程分支或改写远程历史，除非用户明确提出并再次确认目标。
- 禁止自动 stash、丢弃或覆盖用户未提交改动；未提交改动阻塞同步时停止并报告。
- 不修改全局 Git 用户名、邮箱或身份配置。
- 不把密码、token、私钥写入仓库、命令历史或输出；认证失败时说明原因和下一步（例如检查 gh/SSH 登录），不要要求用户粘贴密钥。
- 只负责远程同步相关操作，不顺便执行无关重构、提交或发布任务；本地提交请使用“提交到git”任务。
