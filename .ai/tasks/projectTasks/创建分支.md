# 创建分支

为当前项目创建独立 Git 分支工作目录，并在新的 Cursor 窗口中打开，供该分支独立开发。

## 目标

1. 在当前项目同级维护统一的 `<项目名>-fz/` 分支工作区容器。
2. 用 Git worktree 为需求创建独立分支目录，避免多个分支共用同一工作区。
3. 用独立 Cursor 窗口打开新分支目录。

## 输入

- 用户的需求描述、期望分支名或目录名。
- 用户未指定时，根据需求生成简短、可读的英文 kebab-case 名称：
  - Git 分支：`feature/<需求名>`。
  - 工作目录：`<需求名>`（不包含 `/`）。
- 基准分支由用户指定时优先使用；否则以当前检出的 `HEAD` 为基准。
- 只有无法从需求判断分支用途或名称时才询问用户。

## 执行步骤

1. 确认当前目录位于 Git 仓库中，取得：
   - 项目根目录：`git rev-parse --show-toplevel`
   - 当前分支：`git branch --show-current`
   - 当前提交：`git rev-parse HEAD`
   - 工作区状态：`git status --short`
2. 计算目录：
   - 项目名：项目根目录的文件夹名。
   - 分支容器：项目根目录旁边的 `<项目名>-fz/`。
   - 分支目录：`<项目名>-fz/<需求名>/`。
3. 检查分支容器：
   - 不存在则创建。
   - 已存在目录则复用。
   - 同名路径若不是目录，或分支目录已存在但不是目标 Git worktree，停止并说明冲突；不要覆盖。
4. 如配置了远程仓库，先执行只读更新：`git fetch --all --prune`。拉取失败时说明原因；本地基准提交可用则允许继续创建本地分支。
5. 创建独立 worktree：
   - 新分支不存在：`git worktree add -b <分支名> <分支目录> <基准引用>`。
   - 分支已存在且未被其它 worktree 占用：`git worktree add <分支目录> <分支名>`。
   - 分支已在其它目录检出：复用并打开已有 worktree，不要重复创建。
6. 在分支目录内验证：
   - `git rev-parse --show-toplevel` 等于分支目录。
   - `git branch --show-current` 等于目标分支。
   - `git status -sb` 正常。
7. 用新的 Cursor 窗口打开分支目录：优先 `cursor -n "<分支目录>"`（或当前环境等价的“新窗口打开文件夹”命令）。若 Cursor CLI 不可用，保留已创建 worktree，并把绝对路径告知用户手动打开。
8. 回复分支名、基准引用、分支目录绝对路径、Cursor 打开结果。

## 产出

- 同级 `<项目名>-fz/` 容器。
- `<项目名>-fz/<需求名>/` 独立 Git worktree。
- 一个打开该分支目录的独立 Cursor 窗口。

## 约束

- 使用 `git worktree`，不要复制整个仓库，也不要让多个分支在主项目目录反复 checkout。
- 当前工作区的未提交修改不会自动进入新 worktree；不得擅自复制、stash、提交或丢弃。若需求必须包含这些修改，先询问用户如何处理。
- 不使用强制删除、强制切换、hard reset 等破坏性命令。
- 不自动 push 分支，除非用户明确要求。
- 分支目录只能位于同级 `<项目名>-fz/` 下；不要在项目根目录堆分支副本。
- 需求清晰时直接创建；仅在命名、基准或路径冲突无法安全处理时询问用户。
