# 合并分支

在主线 Cursor 窗口中，从同级 `<项目名>-fz/` 选择一条已提交分支合并到主线；一次只合并一条，验证成功后安全清理该分支 worktree。

## 目标

1. 只列出已提交、工作区干净且尚未合入主线的分支。
2. 询问用户本次先合并哪一条；每次执行最多合并一条。
3. 处理冲突并完成验证后，以 `--no-ff` 保留分支历史，再安全移除对应 worktree 与本地分支。

## 主线环境校验（必须先执行）

1. 检查当前 Cursor 窗口：
   - `git rev-parse --is-inside-work-tree`
   - `git rev-parse --show-toplevel`
   - `git branch --show-current`
   - `git status -sb`
   - `git worktree list --porcelain`
2. 确认：
   - 当前 Cursor 工作区根目录就是当前 Git 根目录。
   - 当前目录是主项目工作区，不位于 `<项目名>-fz/` 中。
   - 当前分支是项目主线分支（优先依据远程默认分支；无法判断时询问用户）。
   - 主线工作区完全干净，且没有正在进行的 merge、rebase、cherry-pick。
3. 条件不满足时停止：
   - 在分支 worktree 中执行：提示回到主线 Cursor 窗口。
   - 主线存在未提交变更：提示先提交或自行处理；不要自动 stash、提交或丢弃。

## 候选分支扫描

1. 计算：
   - 主项目根目录与项目名。
   - 同级分支容器 `<项目名>-fz/`。
2. 使用 `git worktree list --porcelain` 枚举 worktree；只处理路径确实位于该容器下的 linked worktree，不按普通文件夹名称猜测分支。
3. 逐个检查：
   - worktree 路径存在且属于当前仓库。
   - 分支不是 detached HEAD。
   - `git -C <worktree> status --porcelain` 为空（所有开发内容已提交）。
   - 分支有尚未进入当前主线的提交。
4. 分类展示：
   - **可合并**：工作区干净、有未合入提交。
   - **不可合并**：存在未提交内容、分支/路径异常；说明原因并提示在对应窗口执行「分支-提交到git」。
   - **已合并**：提交已全部在主线中；不当作本次合并候选。
5. 对每条可合并分支展示：分支名、worktree 路径、相对主线的提交数量、最近提交摘要。

## 用户选择（强制）

1. 必须询问用户：“本次先合并哪一条已提交分支？”
2. 选项只包含「可合并」分支；若只有一条，也仍需确认。
3. 本次只能选择一条。用户想合并多条时，说明将逐条执行；本次完成后重新运行任务处理下一条。
4. 用户未选择前不得执行 merge，也不得删除任何 worktree。

## 执行步骤

1. 用户选定后，再次确认主线和目标 worktree 均干净，记录：
   - 主线分支与合并前 commit。
   - 目标分支、worktree 路径。
   - 两者 merge-base 与待合入提交列表。
2. 如配置远程，执行 `git fetch --all --prune` 获取远程状态；不自动 pull、rebase 或 push。若主线落后远程，停止并说明，避免在过期主线上合并。
3. 读取 `.ai/tasks/projectTasks/提交到git.md` 的当前版本规则；根据目标分支相对主线的**整体变更体量**计算本次主线正式版本号。
4. 开始单分支合并但暂不提交：
   ```bash
   git merge --no-ff --no-commit <目标分支>
   ```
5. 处理冲突：
   - 先查看冲突文件、两侧意图和相关测试。
   - 明确、机械且低风险的冲突可以直接解决。
   - 涉及产品行为、数据兼容、两套实现取舍时，询问用户后再继续，不擅自选择。
   - 不得用 `--ours` / `--theirs` 批量覆盖所有冲突。
6. 按根目录 `agent.md` 运行受影响测试、静态检查及必要构建：
   - 失败时只修复由本次合并暴露的明确问题并重新验证。
   - 无法安全修复或测试仍失败时执行 `git merge --abort`，保留目标 worktree 与分支，报告原因并停止。
7. 验证通过后创建带版本号的 merge commit，保留完整分支历史：
   ```bash
   git commit -m "$(cat <<'EOF'
   vX.Y.Z 合并分支 <分支名>：<概括合入功能>

   EOF
   )"
   ```
8. 提交后再次验证：
   - `git merge-base --is-ancestor <目标分支> HEAD`
   - `git status -sb`
   - 必要的快速测试
   - `git log --graph --oneline -10`
9. 仅在合并提交与验证均成功后，安全清理**本次这一条**分支：
   ```bash
   git worktree remove "<目标worktree路径>"
   git branch -d "<目标分支>"
   git worktree prune
   ```
   - 禁止使用 `rm -rf` 或 `git worktree remove --force`。
   - 任一步清理失败时保留现场并报告，不影响已完成的 merge commit。
   - `<项目名>-fz/` 为空时可用 `rmdir` 删除空容器；仍有其它分支时必须保留。
10. 回复本次合并的分支、merge commit、正式版本号、冲突处理、验证结果、清理结果，以及尚待处理的分支列表。

## 产出

- 主线上的一个 `--no-ff` merge commit，完整保留所选分支历史。
- 本次合并的测试与诊断结果。
- 已安全移除的目标 worktree 和本地分支（仅成功时）。
- 尚未合并分支的清单，供下次执行时选择。

## 约束

- 一次执行最多合并一条分支；禁止循环自动合并全部候选。
- 合并前必须询问用户选择哪一条，即使只有一个候选。
- 只合并已提交且 worktree 干净的分支；有未提交内容时不得代为提交。
- 合并或验证失败时不得删除 worktree、分支或容器。
- 使用 `--no-ff`，不 squash、不 rebase，确保删除分支后历史仍可追溯。
- 不自动删除远程分支、不 push、不打 tag、不修改 `git config`。
- 不使用 force、hard reset、批量 ours/theirs 等高风险操作。
