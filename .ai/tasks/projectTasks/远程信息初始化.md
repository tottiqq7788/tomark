# 远程信息初始化

根据用户提供的远程信息，将远程仓库/设备记录写入 `.ai/remote/`。

## 目标

1. 解析用户给出的远程信息（主机、仓库路径、访问方式等）。
2. 在 `.ai/remote/` 落盘为可查阅的 Markdown 记录。
3. 写完后告知文件路径与已记录字段摘要。

## 输入

用户消息中的远程信息，例如：主机名/IP、SSH 用户、端口、远程路径、仓库名、git remote URL、用途备注等。能从上下文推断的直接使用；仅当缺少到无法落盘的关键项（如完全不知道记哪台/哪个仓库）时才询问。

## 执行步骤

1. 从用户输入提取远程字段；可识别多项则分别建档。
2. 在 `.ai/remote/` 创建或更新记录文件：
   - 文件名用简短英文或拼音标识（如主机名、仓库短名），以 `.md` 结尾；避免空格与特殊字符。
   - 已有同名文件时合并更新已知字段，不要无故清空未提及的原有信息。
3. 按下方模板写入（有则填、无则省略该行，不要编造）：

```markdown
# <标识名>

## 基本信息

- 用途：
- 主机：
- 端口：
- 用户：
- 远程路径：
- 仓库名：
- Git Remote：
- 访问方式：SSH / 其他

## 备注

<用户补充的其他信息>
```

4. 完成后简要列出写入/更新的文件路径与关键字段，直接完成，不要再确认。

## 产出

- `.ai/remote/<标识>.md` 一份或多份远程信息记录。

## 约束

- 需求清晰时直接写文件，不要向用户反复确认。
- 仅当关键信息缺失、无法继续时再询问用户。
- 只写入 `.ai/remote/` 下的记录文件，不顺便改其他无关内容。
- 不要把明文密码、私钥内容写入仓库；若用户提供了密钥/口令，只记录“已配置/使用某密钥文件名”等非敏感说明，并提醒勿入库。
- 信息不完整时如实省略字段，不要虚构主机、路径或 URL。
