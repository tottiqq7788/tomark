# 打包安装包

按当前设备打出发行安装包，并向用户回报所用 **git 版本** 与产物绝对路径。打包命令、版本同步与产物目录以根目录 `agent.md` 为准；本任务不写死技术栈 CLI。

## 目标

1. 确保 `agent.md` 已说明：如何打包、**如何以 git 的 `vX.Y.Z` 同步产品版本**、各平台产物路径与注意点。
2. 打包前完成版本同步，使安装包文件名/元数据与 git 版本一致（不以配置里过期占位版本为准）。
3. 按当前操作系统产出对应安装包，并回报版本号与最终路径。

## 版本要求（强制）

- **权威来源**：git 中的 `vX.Y.Z`（优先本地 tag；否则最近一次提交说明以 `vX.Y.Z` 开头——与「提交到git」一致）。细则以 `agent.md`「打包安装包 → 版本号」为准。
- **禁止**：在未解析到 git 版本时，沿用 `tauri.conf.json` / `package.json` / `Cargo.toml` 里的旧占位版本（如长期残留的 `0.1.0`）继续打包。
- **找不到版本**：停止并提示先执行「提交到git」，不要猜测版本号。

## 平台产物要求（强制）

先识别当前设备 OS（如 `darwin` / `win32` / 其它）：

| 当前设备 | 必须产出 |
|----------|----------|
| **macOS** | **两种** `.dmg`：Intel（x86_64）与 Apple 芯片（arm64 / aarch64），分别可安装；不要只打一个 universal 就当作交差（除非用户明确只要 universal）。 |
| **Windows** | `.exe` 安装包（如 NSIS / 等价安装程序，以本项目打包工具默认为准）。 |
| **其它 OS** | 按 `agent.md` 中该平台约定产出；若未约定，在 `agent.md` 补写可行方案后再打，或说明本机暂不支持并停止。 |

## 执行步骤

1. 读取根目录 `agent.md`，查找打包 / 安装包 / 版本同步相关说明。
2. **若尚未说明**：结合**当前仓库**的技术栈、目录与构建脚本，在 `agent.md` 写入「打包安装包」约定（含：**git 版本解析与写入哪些文件**、各平台命令、目标架构、产物路径、依赖与签名注意等），写完再继续。
3. **若已经说明**：不要改写技术栈细节，直接按 `agent.md` 执行。
4. 按 `agent.md` 解析并同步产品版本到配置（若构建命令已内置同步则可直接构建，但须确认日志/产物版本正确）。无 git 版本则停止。
5. 识别当前 OS，按上方「平台产物要求」与 `agent.md` 执行打包（mac 须覆盖 Intel + Apple 两套 dmg；win 打 exe）。
6. 定位产物：核对文件名中的版本段与本次 git `vX.Y.Z` 一致；向用户列出所用版本与**最终安装包绝对路径**（mac 应列出两个 dmg）。
7. 失败时根据日志与 `agent.md` 排查（版本同步失败、工具链、目标架构未安装、旧卷占用等）；不要假装成功。

## 产出

- 必要时已更新的 `agent.md`「打包安装包」说明（含版本同步约定）。
- 已与 git `vX.Y.Z` 对齐的产品版本配置（同步产生的 diff 属预期）。
- 符合当前平台要求、且文件名/元数据版本正确的安装包。
- 回复中的：所用 `vX.Y.Z` + 最终打包位置（绝对路径列表）。

## 约束

- 本任务文件不写死具体技术栈或 CLI 命令；一律以当前项目的 `agent.md` 为准。
- `agent.md` 已有打包说明时直接执行，不要另发明流程；但若缺少「以 git 版本为准」的约定，必须先补进 `agent.md` 再打。
- 需求清晰时直接打包，不要反复确认。
- 除补写/完善 `agent.md` 打包说明、以及按约定同步版本配置外，不顺便改业务功能代码、不往 `plan/` 写文档。
- 遵守 `agent.md` 落盘规则；不要把安装包随意堆到仓库根目录（优先构建工具默认的 bundle 目录，或 `agent.md` 指定位置）。
- 本任务不负责创建远程 Release（见「提交 release」）。
