# 开发规划初始化

梳理需求并给出技术栈与目录规划，在仓库根目录（与 `.ai` 同级）完成分类目录及 `agent.md` / `readme.md` 初始化。

## 目标

1. 梳理用户需求，输出可落地的技术栈建议与对应目录结构说明。
2. 在根目录创建 2–5 个技术/模块顶层分类文件夹，覆盖规划中的主要模块。
3. **额外**固定创建 `plan/`（含 `prd/`、`misc/`），用于产品相关规划与产出。
4. 在根目录新增 `agent.md`（给 Cursor 的项目注意事项）与 `readme.md`（公开项目介绍）。

## 输入

- 用户对产品形态、端侧、已有技术偏好、约束（性能、平台、团队熟悉度等）的描述。
- 需求足够提出合理技术栈时直接规划并落盘；关键信息缺失到无法选型时再询问。

## 执行步骤

1. 梳理需求：目标产品、端（桌面/Web/移动等）、核心能力、非功能约束；用简短条目写出理解，不要空泛复述。
2. 给出技术栈规划（展示给用户，作为本次产出的一部分），需包含：
   - 推荐栈及简要理由（示例风格：客户端可用 Tauri + Rust + Vue）。
   - 按该栈展开的**建议目录树**（说明每个顶层目录职责；目录树中须包含下方固定的 `plan/`）。
3. 在仓库根目录创建技术/模块顶层分类文件夹：
   - 数量控制在 **2–5 个**（**不含**下方强制的 `plan`），能覆盖规划即可，不要拆太碎。
   - 命名可用通用名（如 `frontend`、`backend`），或按技术栈/模块命名（如 `src-tauri`、`web`、`server`）；短英文、见名知意。
   - 仅初始化目录结构（可按需放 `.gitkeep` 或最小占位），不要在此步骤大面积生成业务代码。
   - 不改动、不挪动已有的 `.ai/`、`.git/`。
4. **无论**上一步技术/模块文件夹如何命名，都必须额外创建产品规划目录（已存在则补齐子目录，勿清空已有内容）：
   ```text
   plan/
     prd/    # 产品需求、PRD、规格说明等
     misc/   # 产品相关其他规划与产出（调研、纪要、原型备注等）
   ```
5. 在根目录创建/更新两个文件（已存在则按本次规划合并更新，勿无故清空用户已有有效内容）：
   - `agent.md`：面向 Cursor/Agent 的项目注意事项（技术栈约定、目录职责含 `plan/prd` 与 `plan/misc`、禁止事项、常用任务入口如 `.ai/tasks/...` 等）。
   - `readme.md`：面向公开读者的项目介绍（是什么、为何存在、技术栈概览、目录说明含 `plan`、如何开始；勿写入密钥与内网隐私）。
6. 完成后简要汇总：技术栈要点、已创建目录列表（含 `plan/prd`、`plan/misc`）、`agent.md` / `readme.md` 路径；直接完成，不要再确认一遍。

## 产出

- 需求理解与技术栈 + 目录规划说明（写在回复里即可）。
- 根目录下 2–5 个技术/模块分类文件夹。
- 根目录固定目录：`plan/prd/`、`plan/misc/`。
- 根目录 `agent.md`、`readme.md`。

## 约束

- 需求清晰时直接规划并创建，不要反复确认选型；仅当无法合理选型或与现有根目录严重冲突时再询问。
- 技术/模块顶层目录严格 2–5 个；`plan` 为强制附加，不计入这 2–5，也不得用其他名字替代。
- `plan` 下至少包含 `prd`、`misc`；本次不必再往里塞业务代码。
- 技术/模块侧子目录可在规划说明里提到，但本次初始化以顶层覆盖为主，避免过度脚手架。
- 只做规划与结构初始化，不顺便实现业务功能、不强制执行安装依赖或构建。
- `readme.md` 保持可公开；敏感信息只写在本地约定或 `.ai/remote` 等非公开位置，不要写进 readme。
- 若根目录已有同名业务目录，合并进规划并复用/补齐，不要盲目删除已有内容。
