# 初始化开发目录

梳理需求并给出技术栈与目录规划，在仓库根目录（与 `.ai` 同级）完成**开发模块目录**、**依赖目录 `deps/`**，以及 `agent.md` / `readme.md` 初始化；并按规划技术栈**直接下载依赖**。开发源码只进模块目录，不在根目录堆砌。

## 目标

1. 梳理用户需求，输出可落地的技术栈建议与对应目录结构说明。
2. 在根目录创建开发相关顶层文件夹（合计 **2–5 个**，**必须包含 `deps/`**），覆盖主要模块（如 `src/`、`src-tauri/`、`tests/`、`deps/`）。
3. 按规划技术栈在 `deps/`（及栈要求的配套位置）写入依赖清单，并**立即下载/安装**相关依赖。
4. **额外**固定创建 `plan/`（含 `prd/`、`misc/`），用于产品相关规划与产出（不计入上述 2–5）。
5. 在根目录新增/更新 `agent.md` 与 `readme.md`；其中 **`agent.md` 必须明确声明**后续开发的落盘纪律（见下方「agent.md 必写条款」）。

## 输入

- 用户对产品形态、端侧、已有技术偏好、约束（性能、平台、团队熟悉度等）的描述。
- 需求足够提出合理技术栈时直接规划、建目录并拉依赖；关键信息缺失到无法选型时再询问。

## agent.md 必写条款（强制）

新建或更新 `agent.md` 时，**必须用独立小节写清**（不可只在口头规划里提、不可省略），至少包含：

1. **禁止在项目根目录堆砌开发文件**（组件、页面、业务脚本、样式、语言源文件、测试用例等不得直接落在根上）。
2. **后续持续开发过程中**，所有代码与测试必须按**本次初始化形成的开发目录**存放（例如 `src/`、`src-tauri/`、`tests/` 及其子目录），不得绕过这些目录另起炉灶。
3. **`deps/` 为依赖专用目录**：包清单、锁文件、包管理器安装目录（如 `node_modules`）等放此处；不要把业务源码塞进 `deps/`，也不要在根目录另起一套依赖堆。
4. 顶层开发相关文件夹保持 **2–5 个**（含 `deps/`）；若不够用，须先询问用户是否可以增加「XXX」文件夹，同意后再建。
5. 列出本次初始化的各开发目录及其职责（含 `deps/`），作为长期落盘依据。

以上条款是给后续 Agent / 开发任务看的长期约定，不是仅限初始化当次的提示。

## 执行步骤

1. 梳理需求：目标产品、端（桌面/Web/移动等）、核心能力、非功能约束；用简短条目写出理解，不要空泛复述。
2. 给出技术栈规划（展示给用户），需包含：
   - 推荐栈及简要理由（示例风格：客户端可用 Tauri + Rust + Vue）。
   - 按该栈展开的**建议目录树**（每个顶层开发目录的职责；**必须含 `deps/`** 与固定的 `plan/`）。
   - 依赖方案：哪些包进 `deps/`、用什么包管理器、Rust/其他生态若需与模块目录绑定（如 `src-tauri/Cargo.toml`）如何配合。
   - 明确：**业务/源码/测试只进开发目录；依赖进 `deps/`（及栈约定的配套清单位置）；根目录不堆砌；纪律写入 agent.md 并持续遵守**。
3. 在仓库根目录创建开发相关顶层文件夹：
   - 数量控制在 **2–5 个**（**不含** `plan`、`.ai`、`.git`），且 **其中必须包含 `deps/`**。
   - 其余命名贴合技术栈（如 `src`、`src-tauri`、`tests`）；短英文、见名知意。
   - 仅初始化目录结构（可按需 `.gitkeep` 或最小占位），**不要**在根目录创建成批业务源码文件。
   - 不改动、不挪动已有的 `.ai/`、`.git/`。
4. **同步新增/确认 `deps/`**（已存在则复用，勿清空用户已有有效依赖配置）：
   - 用途：存放与技术栈相关的依赖清单、锁文件、安装产物目录等。
   - 典型（Node/前端）：在 `deps/` 下维护 `package.json`（及 lock），`node_modules/` 安装于此；不要把 `node_modules` 堆在仓库根目录。
   - 典型（Rust/Tauri）：crate 清单可仍在 `src-tauri/Cargo.toml`（生态惯例）；若需本地 vendor/缓存目录，优先放在 `deps/` 下并在 `agent.md` 说明，避免根目录散落。
   - 其他栈同理：依赖相关文件归 `deps/` 或模块内惯例路径，并在规划与 `agent.md` 写清。
5. **按规划技术栈直接下载依赖**（初始化必做，不要留到「以后再说」）：
   - 根据栈写入最小可用依赖清单（能支撑后续开发与文档中的选型，如 Vue/Vite/Tauri 相关包等）。
   - 在对应目录执行安装/下载，例如：
     - Node：`npm install` / `pnpm install` / `yarn`（在 `deps/` 或工作区约定路径执行）。
     - Rust：`cargo fetch` 或在 `src-tauri` 下 `cargo build` 所依赖的获取步骤（按环境可行性选择较轻量的下载方式）。
   - 安装失败时：记录错误、尝试可自动修复的配置问题；仍失败则在汇总里说明原因与补救命令，不要假装已安装成功。
   - 本步是**拉依赖与清单落地**，仍不要借机大面积实现业务功能。
6. **无论**模块目录如何命名，都必须额外创建产品规划目录（已存在则补齐，勿清空已有内容）：
   ```text
   plan/
     prd/    # 产品需求、PRD、规格说明等（本仓库：先开发，再归档）
     misc/   # 产品相关其他规划与产出
   ```
7. 在根目录创建/更新 `agent.md` 与 `readme.md`：
   - **`agent.md`（强制）**：技术栈、目录职责（含 `deps/`）、完整「开发落盘规则」（按「agent.md 必写条款」）、依赖安装位置与常用命令、禁止事项、任务入口。缺任一必写条款视为未完成。
   - `readme.md`：公开介绍（是什么、技术栈概览、目录说明含 `deps`、如何安装依赖与开始；勿写密钥与内网隐私）。
8. 汇总：技术栈要点、2–5 个开发目录（须含 `deps/`）、依赖安装结果、`plan/prd`/`plan/misc`、确认 `agent.md` 已写入落盘与依赖约定；直接完成。

## 产出

- 需求理解与技术栈 + 目录规划说明（写在回复里即可）。
- 根目录下 2–5 个开发相关文件夹（**含 `deps/`**）。
- 已按技术栈下载/安装的依赖（或失败时的明确说明与补救命令）。
- 根目录固定目录：`plan/prd/`、`plan/misc/`。
- 根目录 `agent.md`（含强制落盘与 `deps` 条款）、`readme.md`。

## 约束

- 需求清晰时直接规划、建目录并拉依赖；仅当无法合理选型或与现有根目录严重冲突时再询问。
- 开发相关顶层目录严格 **2–5 个**，且 **必须包含 `deps/`**；`plan` 为强制附加，不计入这 2–5。
- **初始化阶段不要在根目录堆砌开发源码**；占位放在模块目录内；依赖进 `deps/`，不要在根上再堆一套 `node_modules`。
- **`agent.md` 未声明「禁止根目录堆砌 + 持续开发须按初始化目录存放 + deps 职责」则不得视为任务完成**；更新已有 `agent.md` 时合并进上述条款，勿冲掉。
- 若判断还需要额外顶层开发文件夹（在已含 `deps` 的 2–5 之外）：先问用户「是否可以增加 XXX 文件夹」，同意再建。
- `plan` 下至少含 `prd`、`misc`；本次不必往里塞业务代码。
- 必须下载规划栈的相关依赖；但不要顺便实现完整业务功能或强行做发布构建（除非验证依赖所必需的最小命令）。
- `readme.md` 保持可公开；敏感信息放 `.ai/remote` 等非公开位置。
- 若根目录已有同名业务目录或已有 `deps/`，合并进规划并复用/补齐，不要盲目删除已有内容。
