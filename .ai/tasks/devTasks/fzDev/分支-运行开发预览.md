# 分支-运行开发预览

在当前独立分支 worktree 中启动专属开发预览，确保工作目录、依赖、进程和端口不与主项目或其它分支冲突。

## 目标

1. 确认当前 Cursor 窗口打开的是正确的分支 worktree。
2. 按当前分支 `agent.md` 的技术栈和预览规则启动开发模式。
3. 为本分支分配并验证独立端口/进程，保持热更新、快启动、易排查。

## 分支环境校验（必须先执行）

1. 检查：
   - `git rev-parse --show-toplevel`
   - `git branch --show-current`
   - `git status -sb`
   - `git worktree list --porcelain`
2. 确认当前 Cursor 工作区根目录就是当前 Git 根目录，且它位于 `<项目名>-fz/<分支目录>/` 下，是当前分支的独立 linked worktree。
3. 条件不满足时停止，提示用户先执行「创建分支」或在独立 Cursor 窗口打开正确目录；禁止从主项目目录替分支启动预览。

## 执行步骤

1. 读取**当前 worktree 内**的 `agent.md`：
   - 已说明开发预览：直接遵守。
   - 未说明：结合当前分支的技术栈、脚本与架构，在当前 worktree 的 `agent.md` 补写通用预览规则后再启动。
2. 检查当前分支是否已有预览进程：
   - 只有进程工作目录属于当前 worktree，才可视为本分支进程并复用。
   - 主项目或其它 worktree 的同类进程不得复用、停止或覆盖。
3. 识别预览涉及的全部端口（前端、后端、桌面壳 dev URL、调试/热更新端口等），同时检查系统监听端口和现有预览进程。
4. 为当前分支选择独立端口：
   - 默认端口空闲时可以使用。
   - 已占用时，自动选择可用端口，并对该分支涉及的所有配置/参数保持一致。
   - 优先使用环境变量或 CLI 参数做运行时覆盖，不修改已提交的公共配置。
   - 技术栈无法运行时覆盖时，可在当前 worktree 内生成**已忽略、仅本分支运行时使用**的临时配置；不得提交，也不得改其它 worktree。
5. 在当前 worktree 目录中准备该分支自己的依赖/缓存（遵守 `agent.md`），启动开发预览并长期挂起。不要从原项目路径运行命令。
6. 启动后验证：
   - 所需端口均由当前 worktree 的进程监听。
   - 页面/窗口可访问。
   - 热更新连接正常。
   - 日志没有端口回退、绑定失败或误连其它分支服务。
7. 回复当前分支名、worktree 绝对路径、启动命令、实际端口/URL、进程信息和停止方法。

## 产出

- 当前分支独立运行的开发预览进程。
- 与其它 worktree 不冲突的端口/URL。
- 访问方式、日志位置（如有）与停止方法。

## 约束

- 本任务不写死技术栈或固定端口；以当前分支 `agent.md`、脚本和配置为准。
- 所有命令必须在当前 worktree 中运行；不得使用原项目或其它分支的依赖目录、构建缓存与工作目录。
- 不得杀掉、复用或抢占其它分支/主项目的预览进程和端口。
- 端口冲突时自动换空闲端口；不要要求用户手动关闭其它分支来让路。
- 日常预览只用开发模式，不用生产打包替代。
- 除必要的当前分支 `agent.md` 预览说明或已忽略的临时运行配置外，不改业务代码、不写 `plan/` 文档。
