# 分支-新增功能审查

仅在当前独立分支 worktree 中审查该分支相对基准分支的全部新增功能；明确必须修复的问题直接在本分支修复并补测。

## 目标

1. 确认当前 Cursor 窗口、worktree 与 Git 分支正确且相互对应。
2. 审查本分支相对基准的提交及未提交改动，覆盖相关模块。
3. 只在当前分支修复必须项，验证后给出分类结论。

## 分支环境校验（必须先执行）

1. 检查：
   - `git rev-parse --show-toplevel`
   - `git branch --show-current`
   - `git status -sb`
   - `git worktree list --porcelain`
2. 确认当前 Cursor 工作区根目录就是当前 Git 根目录，且它是位于 `<项目名>-fz/<分支目录>/` 下的独立 linked worktree；当前分支不得是 detached HEAD。
3. 条件不满足时停止，提示先执行「创建分支」或在独立 Cursor 窗口打开正确目录；禁止转去主项目工作区执行审查/修复。

## 执行步骤

1. 确定基准分支：
   - 用户指定则优先。
   - 否则优先远程默认分支（如 `origin/main` / `origin/master`）。
   - 无远程默认分支时，根据 worktree 与分支历史选取可靠的共同基准；仍无法判断才询问用户。
2. 用 `git merge-base` 确定共同祖先，审查范围至少包含：
   - `<merge-base>...HEAD` 的全部分支提交差异（不能只看最后一次提交）。
   - 当前 worktree 的已暂存与未暂存差异。
   - 改动文件依赖的相关模块与测试。
3. 先只读审查：
   - bug、回归、边界条件、数据迁移与安全风险。
   - 大文件、超长函数、职责混杂、模块边界不清。
   - 死代码、未使用代码、重复逻辑、过期兼容路径与示例遗留。
   - 测试缺口、错误断言、缺失的跨分支回归覆盖。
4. 可用便宜模型 / subagent 并行检查复杂度、模块边界、死代码与测试；所有代理必须只分析当前 worktree 和本分支 diff，主代理负责去重与定级。
5. 结论分为：
   - **必须修复**：错误、数据丢失、回归、安全风险或明显测试缺口。
   - **建议优化**：结构、维护性、组件拆分与重复逻辑等非阻塞问题。
   - **暂不处理**：需产品/兼容确认，或修复风险高于收益。
6. 对必须修复项，直接在当前 worktree 内最小化修改并补充必要测试；建议优化与暂不处理项不顺手改。
7. 运行受影响测试、静态检查与诊断；无法运行时说明原因。最后检查 `git status -sb` 和 `git diff --stat`。

## 产出

- 分支审查范围（当前分支、基准分支、merge-base）。
- 已直接修复的问题及测试改动。
- 建议优化、暂不处理事项。
- 执行过的验证命令及结果。

## 约束

- 所有改动与命令必须限定在当前分支 worktree；禁止修改原项目或其它分支目录。
- 先只读、后定级、再修必须项；禁止借审查扩大重构范围。
- 不自动提交、合并、rebase 或 push。
- 遵守当前分支 `agent.md` 的代码落盘与依赖规则。
- 不向 `plan/` 写审查文档，除非用户明确要求。
