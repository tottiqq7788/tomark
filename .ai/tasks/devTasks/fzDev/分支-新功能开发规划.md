# 分支-新功能开发规划

仅在当前独立分支 worktree 与对应 Cursor 窗口中规划并开发新功能，不影响主项目工作区或其它分支。

## 目标

1. 确认当前 Cursor 窗口打开的是 `<项目名>-fz/<分支目录>/` 对应 Git 分支。
2. 在 Plan 模式中给出贴合当前分支和技术栈的可执行规划。
3. 用户确认后，只在当前分支工作目录内实现并验证。

## 输入

- 用户的新功能需求。
- 当前分支中的 `agent.md`、`readme.md`、源码、依赖与测试约定。
- 需求足够明确时直接规划；缺少关键产品决策、无法继续时再询问。

## 分支环境校验（必须先执行）

1. 取得当前 Cursor 工作区、Git 根目录、分支与 worktree 信息：
   - `git rev-parse --show-toplevel`
   - `git branch --show-current`
   - `git status -sb`
   - `git worktree list --porcelain`
2. 确认：
   - 当前 Cursor 工作区根目录就是当前 Git 根目录。
   - 当前目录是独立 linked worktree，位于同级 `<项目名>-fz/<分支目录>/` 中。
   - 当前分支不是 detached HEAD，且分支名与该 worktree 记录一致。
3. 任一条件不满足时停止开发，告知用户先执行 `.ai/tasks/projectTasks/创建分支.md`，或用独立 Cursor 窗口打开正确分支目录；不得在主项目工作区代替执行。

## 执行步骤

1. 若当前不是 Plan 模式，先切换到 Plan 模式。
2. 只读取**当前 worktree 内**的 `agent.md`、`readme.md`、相关源码、测试和必要的历史差异；不要从原项目目录直接修改文件。
3. 在 Plan 模式中给出：
   - 当前分支名、工作目录与本次功能范围。
   - 要改/新增的模块路径（遵守当前分支 `agent.md` 落盘规则）。
   - 实现步骤、关键流程、边界条件、测试与验收方式。
   - 与基准分支可能冲突的模块及风险。
4. 涉及界面时，在 Plan 对话中提供文字线框图，例如：
   ```text
   ________________________
   |        页面标题        |
   |______________________|
   | 导航  |    主内容区     |
   |______|________________|
   ```
5. 等待用户确认规划；确认后切回 Agent（或等价可执行模式），只在当前 worktree 中实现。
6. 实现后运行当前分支相关测试与诊断，并用 `git status -sb`、`git diff --stat` 汇总改动。

## 产出

- Plan 模式中的详细开发规划。
- 用户确认后的当前分支代码与测试改动。
- 验证结果和当前分支改动摘要。

## 约束

- 所有读取、写入、安装、测试命令的工作目录必须在当前分支 worktree 内。
- 禁止改动原项目工作区、其它 worktree 或其它分支文件。
- 禁止因本任务向 `plan/` 写规划文档；本项目先开发，再另行归档 PRD。
- 不在项目根目录堆业务代码；遵守当前分支 `agent.md` 的目录规则。
- 未获用户确认 Plan 前，不进行大规模代码实现。
- 不自动提交、合并、rebase、push；除非用户另行明确要求。
