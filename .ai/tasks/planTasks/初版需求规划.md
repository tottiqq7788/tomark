# 初版需求规划

根据用户需求与当前技术栈，产出一份可落地的初版需求规划，并写入 `plan/`。

## 目标

1. 结合用户表述与仓库已有技术栈/目录约定，梳理初版需求。
2. 形成结构化初版规划（范围、能力、约束、分期建议等），并落盘。
3. 在回复中给出规划摘要与文件路径。

## 输入

- 用户对本期/本产品的需求描述（目标、场景、必须有/不要有、优先级暗示等）。
- 当前技术栈与项目约定：优先从根目录 `agent.md`、`readme.md`、已有顶层目录及 `.ai/` 约定推断；用户若当场补充栈信息则一并采用。
- 需求足以起草初版时直接规划并落盘；缺到无法判断「做什么」时再询问。

## 执行步骤

1. 读取当前技术栈与结构上下文（有则读，无则跳过并在规划中注明“栈未初始化/待确认”）：
   - `agent.md`、`readme.md`
   - 根目录顶层模块文件夹
   - 已有 `plan/prd/`、`plan/misc/` 中相关文档（避免与已有规划矛盾或重复堆砌）
2. 梳理用户需求：目标用户/场景、核心问题、必须能力、非目标（明确不做）、约束（平台、性能、工期等）；用短条目写出理解。
3. 结合当前技术栈做初版规划，至少覆盖：
   - 产品一句话定位
   - 范围与非目标
   - 核心功能列表（可标 P0/P1）
   - 与现有技术栈的映射（哪些能力落在哪一层/哪个目录，明显不匹配处标出风险或建议）
   - 初版交付边界（第一版做到什么算完成）
   - 待决问题（仅列真正阻塞项；能合理默认的不要塞进待决）
4. 落盘（目录不存在则先创建 `plan/prd`、`plan/misc`）：
   - 主文档写入 `plan/prd/`，文件名简短英文或拼音+日期可选，如 `prd-v0.md` 或 `初版需求.md`
   - 过程性材料（竞品摘录、讨论纪要、备选方案）放 `plan/misc/`，不要塞进主 PRD
5. 回复中给出摘要 + 文件路径；直接完成，不要再确认是否保存。

## 产出

- `plan/prd/` 下的初版需求规划文档一份。
- 如有必要，`plan/misc/` 下的补充材料。
- 回复中的规划摘要。

## 约束

- 归类为规划任务：只做需求/范围规划，不在此任务中改业务代码或大规模改目录。
- 需求清晰时直接写文档；仅当关键需求缺失到无法起草，或与既有 `plan/prd` 严重冲突需用户抉择时再询问。
- 规划必须贴合**当前**技术栈，不要假设尚未采用的栈；若栈信息缺失，在文档中标明假设并尽量保守。
- 这是「初版」：完整可读即可，避免写成空洞愿景或过细到实现细节的设计说明书。
- 不把密钥、内网地址、账号密码写入 `plan/` 文档。
